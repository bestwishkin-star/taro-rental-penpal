# 空间记录与居住可信依据实施计划

## Overview

按合同优先、垂直切片方式实现六点空间记录。先建立草稿和单点保存闭环，再接入三维房屋状态和发布，最后增加可信依据。现有故事接口保持兼容，私密核验资料与公开内容从数据层开始隔离。

## Architecture Decisions

- 新建草稿资源，不把未完成内容写入公开 `rentals`，从查询层消除草稿泄漏风险。
- 空间记录使用固定模块枚举，场景答案保存 `promptId + value + promptVersion`，允许未来改题不破坏历史数据。
- 发布使用数据库事务生成现有故事聚合，旧页面依旧读取 `experience` 和 `photos`。
- 完整度与可信依据均由服务端派生，前端只渲染结果。
- 私密照片单独存表并在 repository 映射阶段过滤，不依赖前端隐藏。
- 所有业务照片引用统一 `photo_assets`，分析任务通过供应商无关 adapter 异步执行，避免未来更换 AI 或安全审核服务时改动业务接口。

## Dependency Graph

```text
共享合同与 SQL 表
  -> 草稿 repository/service
    -> 草稿 API 与前端 service
      -> 单点记录页面
        -> 三维房屋完成度
          -> 事务发布与公开详情
            -> 微打卡与可信依据
```

## Phases

### Phase 1: 草稿基础

1. 定义共享合同、模块题目结构和错误语义。
2. 添加图片资产、分析任务、草稿、空间记录、空间照片表及凭证核验字段迁移。
3. 实现当前草稿创建/读取、所有权校验和服务端完成度计算。
4. 改造上传响应并建立图片指纹、安全审核状态和异步分析 adapter 边界。

### Checkpoint 1

- 未登录和越权访问被拒绝。
- 重复创建返回同一未发布草稿。
- 私密照片 URL 不进入公开映射。

### Phase 2: 单点记录闭环

5. 实现单点读取、自动保存和照片绑定接口。
6. 增加前端 API service 和点位任务页路由。
7. 实现拍摄、日常场景、具体事件、空间切片四个原子组件。
8. 接入自动保存、失败重试、离开恢复、照片可见性和分析进度。

### Checkpoint 2

- 任一点位可从三维房屋进入、保存、退出并恢复。
- 完成条件由服务端判定，前端不能伪造完成状态。
- 相机照片可设为公开或仅核验。

### Phase 3: 房屋状态与发布

9. 三维页读取草稿摘要，点亮已完成模块并跳转正确路由。
10. 实现六点发布校验、安全状态门禁和事务发布，生成兼容的故事摘要与公开封面。
11. 扩展公开详情合同和页面，以空间切片为主体展示新故事，并兼容旧故事。

### Checkpoint 3

- 六点未完成不可发布，六点完成后只发布一次。
- 旧列表、我的屋檐记、收藏、历史和评论链路继续工作。
- 公开详情不含任何私密 URL。

### Phase 4: 可信依据

12. 实现微打卡记录与跨七天、跨时段判定。
13. 扩展私密凭证核验状态和公开可信依据摘要。
14. 接入可替换的家庭空间一致性分析，并在详情页展示解释性可信标识，不显示数值分数。

### Checkpoint 4

- 仅满足规则时显示 `连续居住记录`。
- 凭证与核验照片只对所有者或管理员可见。
- 异常标记不向公开接口泄漏内部原因。

## Risks And Mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| 小程序相机/上传中断导致内容丢失 | 高 | 每步自动保存，上传和记录保存分离，提供显式重试 |
| 发布事务部分成功 | 高 | 草稿校验、故事创建、记录关联在单一事务内完成 |
| 私密照片被公开接口带出 | 高 | 独立表、repository 白名单映射、专项测试 |
| AI 或安全服务超时影响填写 | 高 | 上传与分析异步解耦、有限重试、发布时仅检查归一化状态 |
| AI 误判真实家庭照片 | 高 | 一致性结果只作为复核信号，禁止单模型自动定性 |
| 厂商接口变化造成业务改造 | 中 | `PhotoAnalyzer` adapter、版本化策略和统一结果枚举 |
| JSON 场景答案难以演进 | 中 | 保存题目版本和稳定 promptId，读取时兼容旧版本 |
| 六点任务过重导致放弃 | 中 | 单点可独立完成、自动续填、清晰显示剩余模块 |
| 现有动态列兼容逻辑增加复杂度 | 中 | 新表使用明确 schema，现有 `rentals` 只做发布聚合 |

## Commit Strategy

按用户要求，后续提交时使用中文并按内容拆分：

1. `文档：定义空间记录与可信依据方案`
2. `功能：增加空间记录草稿合同与数据结构`
3. `功能：实现空间点位记录后端接口`
4. `功能：实现空间点位沉浸式补充页面`
5. `功能：接入三维房屋进度与故事发布`
6. `功能：增加连续居住记录与可信依据`

## Verification Handoff

代码阶段会编写聚焦测试用例，但遵循用户要求不执行测试、构建或可视化验收。每个任务会列出应运行命令和真机检查点，由用户统一测试。
