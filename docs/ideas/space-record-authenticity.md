# 空间记录与居住可信依据

## Problem Statement

如何让真实居住者用轻量、有参与感的方式还原一套房子的日常体验，同时允许其保护隐私，并让阅读者看懂内容有哪些可信依据，而不是被一个无法解释的“真实性分数”误导。

## Recommended Direction

把一次长表单拆成六个可独立完成的空间记录任务：厨房、厕所、客厅、房间、楼道、周边环境。用户从三维房屋点击高亮点进入任务页，依次完成“拍下此刻、还原日常、讲一件具体发生过的事、生成空间切片”。每次保存后返回三维房屋，对应空间点亮，房屋亮度继续表达填写完整度。

真实性采用分层依据，而不是单一照片或分数。六个空间均要求现场照片，照片可选择公开或仅用于核验；发布后可通过跨日期、跨时段的微打卡，以及可选的打码居住凭证，获得可解释的公开标识。系统只描述已获得的证据，不承诺内容绝对真实。

## Key Assumptions to Validate

- [ ] 用户愿意完成六个 2-4 分钟的空间任务；通过草稿恢复率和六点完成率验证。
- [ ] “具体事件 + 影响 + 应对”比评分和标签更能帮助读者判断居住体验；通过详情页停留和收藏行为验证。
- [ ] 照片私密核验模式能降低隐私顾虑；通过私密照片占比和任务放弃率验证。
- [ ] 三次、至少跨七天的微打卡不会造成过重负担；通过邀请打开率和完成率验证。

## MVP Scope

- 六个空间点位的独立任务页、服务端草稿和断点续填。
- 每点至少一张现场照片，支持公开或仅核验。
- 图片上传后进入异步分析流水线，首版完成重复图片指纹和安全状态占位，后续可接入家庭空间一致性模型与图片安全服务。
- 模块化场景问题、具体事件文字或语音、空间切片预览。
- 六点完成后发布，既有故事列表和详情接口向后兼容。
- 发布后微打卡和可选打码凭证，详情页展示可信依据标识。

## Not Doing (and Why)

- 不展示真实性百分比或排行榜：证据强度无法准确等同于内容真假。
- 不强制公开照片、地址或凭证：避免暴露住址与生活轨迹。
- 不使用定位作为硬门槛：室内定位误差大，也会显著增加隐私风险。
- 不要求连续每日打卡：容易产生机械应付和伪造，跨时段抽样更有效。
- 不在首版做自动图片内容识别：成本和误判风险高，先保留挑战记录与异常标记能力。
- 不把 AI 判断当作真实性结论：模型只能提供一致性和风险信号，疑似异常需要其他证据或人工复核。

## Open Questions

- 语音在首版是直接公开播放，还是仅转写后由用户确认公开。
- 凭证核验首版由管理员人工处理，还是只记录“已提交、待核验”。
